# 角色卡审查清单（agent 评审提示词）

> 用法：把卡 JSON + 背景资料交给审查 agent，按下面三张清单逐项过。
> 沉淀自芙宁娜卡两轮评审闭环（考据 7.5→性格 8.5/10 全修复，2026-09-05）。

## 一、考据审查

1. **官方设定一致性**：角色背景、时间线、人际关系与官方资料（角色故事、语音、活动剧情）逐条对照，冲突处列出原文出处。
2. **时代锚点正确性**：卡内涉及的每个时代/时期，其角色认知边界是否画对——她那时知道什么、不知道什么、在担心什么。
3. **专有名词**：地名/组织/事件/称谓写法与官方中文一致（如「欧庇克莱歌剧院」非「歌剧院」泛称）。
4. **史料密度**：Lorebook 是否覆盖了卡机制依赖的关键背景（缺一条可能导致信息差机制失效）。

## 二、性格审查

1. **口癖与语气**：first_mes / mes_example 是否体现角色标志性语气（自称、句尾、敬语层次）。
2. **双标签检验**：personality 的标签组合是否互相支撑而非矛盾（如「口嫌体正直+傲娇底色」是互补）。
3. **破绽设计**：机制要求的「破绽不是开关」是否在示例中有体现——破绽应为渐变（进度条/判据），非一句话 toggle。
4. **OOC 风险点**：列出 3 个最容易被模型演崩的场景，检查卡文本是否有对应锚点。

## 三、机制审查

1. **铁律可执行性**：每条铁律是否具体到模型能照做（「保持一致」不可执行，「输出前逐字段比对上次状态栏」可执行）。
2. **信息差闭环**：角色「不该知道的信息」是否有明确条款+判据，而非只靠常识。
3. **输入解析规则**：客观事实 vs 期望预设的区分是否有触发自查清单（防模型照单全收）。
4. **跨卡移植纪律**：本卡新增机制是否为该卡定制？从其他卡移植机制是否经过拍板？（教训：845aa77）
5. **压测覆盖**：卡每个特有机制是否至少有一条探针盯着？探针预期（expect）是否可判定？
